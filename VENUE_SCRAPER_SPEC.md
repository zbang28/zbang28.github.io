# Venue Scraper + Integration Spec

Scrape World Cup watch-party venues from **worldcup.nyc** and integrate them
end-to-end into this project. Target: **15 venues per neighborhood** across all
**156 NYC neighborhoods**.

**HARD CONSTRAINT — zero cost:** no paid APIs, no API keys, no geocoding
services, no new heavy dependencies. Use Node 20's built-in global `fetch` only.

---

## This repo (how it's wired)

- **Express app:** `src/app.js` (routes mounted here). Runs as a local server
  (`src/server.js`) and as a Vercel serverless function (`api/index.js`, which is
  AUTO-GENERATED by `npm run bundle` — never hand-edit `api/index.js`).
- **DB:** Postgres. Schema lives in `src/db.js` `migrate()` (idempotent
  `CREATE TABLE IF NOT EXISTS`). Local dev = Docker PG on `:5433`; prod = Neon
  (`DATABASE_URL` injected by Vercel). Query helpers exported from `src/db.js`:
  `query` / `get` / `all` / `run` (use `$1, $2` placeholders).
- **Seeding pattern:** `src/seed-data.js` (data) + `src/seed.js` (inserts).
  Scripts: `npm run migrate`, `npm run seed`, `npm run reset`.
- **Frontend:** single static `index.html` at repo root. Calls the API via
  `API_BASE` (defined ~line 5507): localhost→local, `*.vercel.app`→same origin,
  else→hardcoded `https://zbang28githubio.vercel.app/api`. Existing data shape
  uses fields: `name`/`venue`, `vtype`, `neighborhood`, `borough`, `perks`,
  `lat`, `lng`, `eventType`.
- **Deploy:** `npm run bundle && vercel deploy --prod` (bundle regenerates
  `api/index.js` from `src/app.js`).

## Source: worldcup.nyc (free, static Astro site, `robots.txt` allows all)

- **Neighborhoods index:** `https://www.worldcup.nyc/neighborhoods/`
  → 156 neighborhood slugs (links of form `/neighborhoods/<slug>/`).
- **Neighborhood page:** `https://www.worldcup.nyc/neighborhoods/<slug>/`
  → lists that neighborhood's venue links (`/venues/<venue-slug>/`) **in display
  order**. Take the **first 15 per neighborhood** (fewer if the neighborhood has
  <15 — Bronx/Staten Island legitimately do; take what exists).
- **Venue page:** `https://www.worldcup.nyc/venues/<venue-slug>/` → static HTML.

### Fields to parse from a venue page

From **JSON-LD** (`<script type="application/ld+json">` blocks — `JSON.parse` each):

- block with `"@type":"BarOrPub"` → `.name`, `.address.streetAddress`, `.url` (website)
- block with `"@type":"BreadcrumbList"` → `itemListElement[2].name` = neighborhood,
  its `.item` ends in the neighborhood slug

From the **page body** (strip HTML tags to text, then regex on labels — these are
PLAIN TEXT, not links):

- `Address: <street>` — e.g. `Address: 132 Havemeyer St`
- `Website: <url>` — e.g. `Website: http://www.banterbrooklyn.com/`
- `Instagram: <@handle>` — e.g. `Instagram: @banterbar`
- `Phone: <number>` — e.g. `Phone: (347) 457-6621`
- `Tags: a • b • c` — e.g. `Tags: soccer • football-bar • supporters` → split on `•` → array
- **Borough:** the subtitle reads `<Neighborhood>, <Borough>` / `<Neighborhood> — <Borough>`.
  Borough is one of: Manhattan, Brooklyn, Queens, Bronx, Staten Island.

### Gotchas (these are placeholders in the source — do not chase them)

- `lat`/`long` in JSON-LD is ALWAYS `40.7128`/`-74.0060` (generic NYC center) —
  fake. Do NOT store as real coords. Leave `lat`/`lng` null. **No geocoding** (it
  would cost money / need keys).
- The hero `<img>` (`/images/heroes/*.jpg`) is a generic stock photo, not a real
  venue photo — do not store as a venue image.
- The description paragraph is templated/generic — skip it or store as-is, but
  don't rely on it.

## Deliverable 1 — scraper (`scripts/scrape-venues.mjs`)

- Pure Node, built-in `fetch` only. No external deps.
- Steps: fetch neighborhoods index → 156 slugs → for each, fetch neighborhood
  page → first 15 venue slugs → dedupe globally → fetch each venue page → parse
  fields above.
- **Politeness + robustness:** concurrency cap ~5, small delay, descriptive
  `User-Agent` header, retry failed requests up to 3× with backoff, and CACHE raw
  HTML to `scripts/.cache/` keyed by URL so re-runs don't re-fetch. Log progress
  (N/total).
- **Output:** `scripts/venues.json` — array of objects with EXACTLY this shape:

```json
{
  "slug": "banter-bar",
  "name": "Banter Bar",
  "neighborhood": "Williamsburg",
  "borough": "Brooklyn",
  "address": "132 Havemeyer St",
  "website": "http://www.banterbrooklyn.com/",
  "instagram": "@banterbar",
  "phone": "(347) 457-6621",
  "tags": ["soccer", "football-bar", "supporters"],
  "vtype": "Sports Bar",
  "source_url": "https://www.worldcup.nyc/venues/banter-bar/"
}
```

- Derive `vtype` from tags: `football-bar`/`sports`→`"Sports Bar"`,
  `restaurant`→`"Restaurant"`, `brewery`→`"Brewery"`, `rooftop`→`"Rooftop"`,
  else `"Bar"`.
- Use `null` for any missing field. Expect ~2,000–2,340 venues total.

## Deliverable 2 — schema + import

Add to `src/db.js` `migrate()` (idempotent) a `venues` table:

```sql
CREATE TABLE IF NOT EXISTS venues (
  id          SERIAL PRIMARY KEY,
  slug        TEXT UNIQUE NOT NULL,
  name        TEXT NOT NULL,
  neighborhood TEXT,
  borough     TEXT,
  address     TEXT,
  website     TEXT,
  instagram   TEXT,
  phone       TEXT,
  vtype       TEXT,
  tags        TEXT NOT NULL DEFAULT '[]',  -- JSON array string, like events.perks
  source_url  TEXT,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_venues_neighborhood ON venues(neighborhood);
CREATE INDEX IF NOT EXISTS idx_venues_borough ON venues(borough);
```

Add `scripts/import-venues.mjs`: reads `scripts/venues.json`, runs `migrate()`,
then UPSERTs each row (`INSERT ... ON CONFLICT (slug) DO UPDATE`) so it's
idempotent and re-runnable. Store `tags` as `JSON.stringify(tags)`. Print final
count.

Add npm scripts:

```json
"scrape": "node scripts/scrape-venues.mjs",
"import-venues": "node scripts/import-venues.mjs"
```

## Deliverable 3 — API route (`src/routes/venues.js`)

- New Express `Router`, mounted in `src/app.js` as
  `app.use('/api/venues', venuesRoutes)`.
- `GET /api/venues?neighborhood=&borough=&q=&limit=` → `{ venues: [...] }`. Parse
  `tags` back to an array in the response. Support `q` `ILIKE` on
  name/neighborhood/address. Default order by neighborhood, name.
- `GET /api/venues/:slug` → `{ venue }` or 404.
- Public (no auth) — these are directory listings.

## Run order / acceptance

1. `npm install` (no new deps should be needed).
2. `node scripts/scrape-venues.mjs` → `scripts/venues.json` has ~2k+ venues, 156
   neighborhoods represented, ≤15 per neighborhood, no entry missing
   name/neighborhood/borough.
3. Start local Docker PG (see README), `npm run migrate`,
   `node scripts/import-venues.mjs` → `venues` table populated.
4. `npm start`, open `http://localhost:4000` → venues view renders;
   `GET /api/venues?borough=Brooklyn` returns Brooklyn venues;
   `GET /api/venues?neighborhood=Williamsburg` returns ≤15.
5. Prod: `npm run migrate` and `node scripts/import-venues.mjs` against Neon
   (`DATABASE_URL`), then `npm run bundle && vercel deploy --prod`.
6. Commit `scripts/venues.json` so the dataset is reproducible.

**Verify nothing in the pipeline calls a paid/keyed service.** Report the final
venue count and any neighborhoods that came back with fewer than 15.
